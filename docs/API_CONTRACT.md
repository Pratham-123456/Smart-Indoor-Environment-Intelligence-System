# SIEIS Data Contract & REST API Specification

## 1. Overview
This document defines the interface agreement between the **ESP32 Edge Sensor Node**, the **Python/Flask Backend**, and the **Web Dashboard Presentation Layer**.

---

## 2. Telemetry Ingestion Contract: `POST /api/sensor`

### 2.1 Request Headers
```http
Content-Type: application/json
```

### 2.2 Ingestion Payload Schema (JSON)
```json
{
  "device_id": "esp32-sieis-01",
  "firmware_version": "1.0.0",
  "sequence_number": 104,
  "uptime_ms": 520000,
  "temperature_c": 23.4,
  "humidity_percent": 51.2,
  "light_raw": 620,
  "light_label": "dim",
  "mq135_adc_mv": 460,
  "mq135_sensor_mv": 690,
  "mq135_status": "ready",
  "sound_swing": 240,
  "sound_do": 0,
  "sensor_status": {
    "dht22": "ok",
    "ldr": "ok",
    "mq135": "ready",
    "sound": "ok"
  },
  "pressure_hpa": null,
  "eco2_ppm": null,
  "tvoc_ppb": null,
  "aqi": null,
  "timestamp": null
}
```

### 2.3 Field Specification

| Field | Type | Required | Physical Range | Semantics & Handling |
|---|---|---|---|---|
| `device_id` | String | Yes | Non-empty string | Unique hardware node identifier |
| `firmware_version` | String | Optional | e.g., `"1.0.0"` | Node firmware version string |
| `sequence_number` | Integer | Yes | $\ge 0$ | Monotonically increasing counter; enforces idempotency |
| `uptime_ms` | Integer | Yes | $\ge 0$ | Node `millis()` elapsed since MCU boot |
| `temperature_c` | Float / Null | No | $-20.0 \dots 70.0$ °C | DHT22 temperature in Celsius |
| `humidity_percent` | Float / Null | No | $0.0 \dots 100.0$ % | DHT22 relative humidity |
| `light_raw` | Integer / Null | No | $0 \dots 4095$ | 12-bit ADC bare LDR divider value |
| `light_label` | String | No | `"dark"`, `"dim"`, `"bright"` | Categorical brightness classification |
| `mq135_adc_mv` | Integer / Null | No | $0 \dots 3300$ mV | Measured millivolts on ESP32 GPIO 34 |
| `mq135_sensor_mv` | Integer / Null | No | $0 \dots 5000$ mV | Estimated sensor AO before 10k:20k divider |
| `mq135_status` | String | Yes | `"warming_up"`, `"ready"`, `"error"` | Operational heater readiness indicator |
| `sound_swing` | Integer / Null | No | $0 \dots 4095$ | Peak-to-peak ADC amplitude across 150ms window |
| `sound_do` | Integer / Null | No | `0` or `1` | LM393 digital threshold comparator state |
| `sensor_status` | Object | Optional | Subsystem map | Individual sensor health flags |
| `pressure_hpa` | Null | - | `null` | Explicitly unsupported (BME280 dropped) |
| `eco2_ppm` | Null | - | `null` | Explicitly unsupported (ENS160 not installed) |
| `tvoc_ppb` | Null | - | `null` | Explicitly unsupported (ENS160 not installed) |
| `aqi` | Null | - | `null` | Explicitly unsupported (uncalibrated gas sensor) |

### 2.4 Response Codes
- `201 Created`: Packet accepted, validated, persisted to SQLite, and intelligence scores computed.
  ```json
  {
    "status": "accepted",
    "observation_id": 42,
    "received_at": "2026-10-19T03:30:00.123456Z",
    "flags": ["OK"],
    "is_valid": true,
    "health_score": 88.5,
    "health_grade": "OPTIMAL"
  }
  ```
- `200 OK`: Duplicate sequence number received from device. Ignored to preserve time-series integrity.
- `400 Bad Request`: Malformed JSON or missing mandatory `device_id`.
- `500 Internal Server Error`: Unhandled database or system exception.

## 3. Query Endpoints

### 3.1 `GET /health`
Returns backend health status, database connectivity, and device freshness.
```json
{
  "status": "healthy",
  "service": "SIEIS Backend",
  "database_status": "connected",
  "server_time_utc": "2026-10-19T03:30:15.000000Z",
  "device_freshness": {
    "is_connected": true,
    "is_stale": false,
    "seconds_since_last": 3,
    "last_seen_at": "2026-10-19T03:30:12.000000Z"
  },
  "total_observations": 120,
  "registered_devices": 1
}
```

### 3.2 `GET /api/readings`
Query parameters:
- `limit` (default: 100, max: 500)
- `device_id` (optional)
- `since` / `until` (ISO8601 UTC string filter)

Returns chronologically sorted observation array from SQLite.

### 3.3 `GET /api/stats`
Aggregates total record counts, active alert count, latest observation, current MQ-135 rolling baseline, and latest Environmental Health Score.

### 3.4 `GET /api/alerts`
Returns active anomalies with severity (`CRITICAL`, `WARNING`, `INFO`), rule name, trigger value, message, and recommendation.

### 3.5 `GET /api/forecast`
Returns 5, 10, and 15-minute linear regression trend projections for temperature, humidity, and gas response with coefficient of determination ($R^2$) and scientific disclaimer.

### 3.6 `GET /api/recommendations`
Returns prioritized actionable operational guidance generated by the rule-based decision support engine.

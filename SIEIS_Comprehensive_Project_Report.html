1. Executive Summary & Problem Formulation

1.1 Motivation & The "Silent Deterioration" Problem

Conventional indoor environmental monitors operate as "dumb displays": they sample sensor pins, convert raw ADC counts into arbitrary numbers, and display them on localized LCDs without semantic context or actionable guidance. Consequently, occupants suffer from four systemic vulnerabilities:

  1. Silent Deterioration: Thermal discomfort, carbon dioxide accumulation, and volatile organic compound (VOC) elevation occur insidiously. Occupants adapt unconsciously to deteriorating air quality until acute cognitive fatigue, headaches, or mucosal irritation manifest.
  2. Reactive Rather Than Proactive Response: Action (e.g., opening windows, engaging HVAC, or dehumidifying) is typically taken long after environmental boundaries have been breached.
  3. Absence of Contextual Guidance: A display indicating "$27.5^\circ\text{C}$" provides no recommendation. Without knowing whether outdoor air is cooler or polluted, an occupant cannot judge whether opening a window will cool the room or introduce particulate matter.
  4. Lack of Automated Trend Analysis: Standard monitoring systems report isolated instantaneous snapshots, completely ignoring rolling baseline drifts, rate of change (first derivative), and short-term forecasting horizons ($+5\text{m}$, $+10\text{m}$, $+15\text{m}$).

1.2 Proposed SIEIS Solution

SIEIS resolves these challenges by implementing a closed-loop Monitor $\rightarrow$ Transmit $\rightarrow$ Analyze $\rightarrow$ Decide architecture: - Monitor: Acquires verified physical telemetry across thermal, hygric, gas, lighting, and acoustic domains using an ESP32 edge node. - Transmit: Employs dual resilient paths—direct USB Serial streaming over COM4 ($115,200\text{ baud}$) and local Wi-Fi HTTP POST telemetry. - Analyze: Computes an authoritative Room Comfort Index (RCI, $0\text{--}100$), calculates experimental indoor $\text{PM}_{2.5}$ and $\text{CO}_2$ proxy estimates, fetches live regional outdoor data for Vellore, and executes Magnus-Tetens psychrometric delta analysis ($\Delta T$, $\Delta\text{RH}$ in percentage points, dew point, absolute moisture in $\text{g/m}^3$). - Decide: Runs a deterministic, 9-rule context-aware diagnostic engine (Rules A through I) that delivers prioritized, explainable guidance and continuous 9-subsystem hardware health monitoring.

2.2 Electrical Safety & Voltage Divider Verification

[!CAUTION] The MQ-135 gas sensor heating element requires a $5.0\text{V}$ supply to reach operating temperature ($\approx 300^\circ\text{C}$). The sensor's analog output ($V_{RL}$) swings between $0\text{ V}$ and $5.0\text{ V}$. Connecting this pin directly to an ESP32 GPIO would exceed the $3.3\text{V}$ absolute maximum rating and cause latch-up destruction.

A passive resistive voltage divider scales the voltage safely: $$V_{\text{pin}} = V_{\text{sensor}} \cdot \left(\frac{R_2}{R_1 + R_2}\right)$$ Using $R_1 = 10\text{ k}\Omega$ and $R_2 = 20\text{ k}\Omega$: $$V_{\text{pin}} = V_{\text{sensor}} \cdot \left(\frac{20}{10 + 20}\right) = V_{\text{sensor}} \cdot 0.667 \implies V_{\text{sensor}} = V_{\text{pin}} \cdot 1.50$$ At maximum sensor saturation ($5.0\text{ V}$), the pin receives: $$V_{\text{pin, max}} = 5.0\text{ V} \cdot \frac{2}{3} \approx 3.33\text{ V}$$ This protects the ESP32 input gate. The firmware converts the measured ADC count into millivolts and reconstructs the sensor voltage: $$V_{\text{pin}}\text{ (mV)} = \left(\frac{\text{ADC}}{4095}\right) \cdot 3300\text{ mV}$$ $$V_{\text{sensor}}\text{ (mV)} = V_{\text{pin}}\text{ (mV)} \cdot 1.50$$

2.3 Explicit Declaration of Unsupported Review 1 Sensors

Following the project's source-of-truth hierarchy, the system does not fabricate readings for components proposed in Review 1 that were not procured: - BME280: Replaced by DHT22. Barometric pressure is honestly reported as unsupported. - ENS160: Not procured. Replaced by the relative baseline MQ-135 channel. True TVOC in ppb and direct eCO₂ are reported as unavailable. - BH1750: Replaced by the bare LDR voltage divider. Calibrated Lux readings are reported as unavailable.

The backend exposes these measurement boundaries via GET /api/hardware-status.

3. Firmware Architecture & Ingestion Subsystems

3.1 ESP32 Edge Firmware (firmware/SIEIS_ESP32/SIEIS_ESP32.ino)

The firmware operates on a non-blocking $5\text{--second}$ acquisition loop (UPDATE_INTERVAL_MS = 5000):

  1. Acoustic Windowing: The LM393 analog output is sampled over a $50\text{--ms}$ sub-window to compute the true peak-to-peak swing: $$V_{\text{swing}} = V_{\text{peak, max}} - V_{\text{peak, min}}$$
  2. DHT22 Reading: Queries the 1-Wire interface with validity verification (isnan checks).
  3. MQ-135 Conditioning: Reads 16-sample averaged ADC on GPIO 34. Tracks a $300\text{--second}$ startup heater warm-up phase (WARMUP_PERIOD_MS = 300000).
  4. LDR Sampling: Reads GPIO 35 and maps to qualitative classifications.
  5. JSON Telemetry Formulation: Formulates a strict, compliant JSON payload with sequence numbers and system uptime.
  6. Dual Transport Transmission:
  7. USB Serial: Emits [JSON] {"device_id": "esp32-sieis-01", ...} over UART at $115,200\text{ baud}$.
  8. Wi-Fi HTTP Client: If connected to local AP, issues POST /api/sensor with a 3-second timeout. If Wi-Fi fails or drops, serial telemetry continues uninterrupted.

3.2 USB Serial Bridge (backend/serial_bridge.py)

A background daemon thread auto-connects to COM4 upon startup: - Performs serial framing and newline-delimited JSON parsing. - Handles legacy formatted fallback strings if flashed with earlier diagnostic test sketches. - Automatically handles physical USB disconnections and reconnects with exponential backoff without crashing the web server.

3.3 Reboot-Aware & Time-Windowed Ingestion (backend/database.py)

To prevent replay attacks and duplicate packet ingestion while accommodating legitimate hardware reboots, insert_observation() uses a dual-condition deduplication algorithm:

# Check for duplicate sequence number if supplied
if seq_num is not None:
    cur = conn.execute(
        "SELECT id, uptime_ms, received_at FROM observations WHERE device_id = ? AND sequence_number = ? ORDER BY id DESC LIMIT 1",
        (device_id, seq_num),
    )
    existing = cur.fetchone()
    if existing:
        is_reboot = False
        uptime_new = data.get("uptime_ms")
        uptime_old = existing["uptime_ms"]
        # If uptime decreases, the ESP32 microcontroller has power-cycled
        if uptime_new is not None and uptime_old is not None and uptime_new < uptime_old:
            is_reboot = True

        # Check time elapsed between previous observation with this sequence number and now
        is_recent = True
        try:
            if existing["received_at"] and data.get("received_at"):
                t_old = datetime.fromisoformat(existing["received_at"].replace("Z", "+00:00"))
                t_new = datetime.fromisoformat(data["received_at"].replace("Z", "+00:00"))
                if abs((t_new - t_old).total_seconds()) > 120:
                    is_recent = False
        except Exception:
            pass

        # Only reject as duplicate if it is within the same session and time window
        if not is_reboot and is_recent:
            logger.warning(f"Duplicate packet received: device {device_id}, seq {seq_num}")
            return existing["id"], True

This prevents the system from rejecting legitimate packets after an ESP32 power cycle.

4. Authoritative Room Comfort Index (RCI) Engine

Implemented in backend/intelligence/rci.py, the RCI provides an authoritative composite score ($0\text{--}100$) reflecting human comfort and indoor environmental safety.

4.1 Sub-Component Scoring Functions

1. Temperature Component Score ($S_T$, Weight $w_T = 0.30$)

Aligned with ASHRAE Standard 55 and CIBSE recommendations: - Optimal Comfort Band: $21.0^\circ\text{C} \le T \le 24.0^\circ\text{C} \implies S_T = 100.0$ - Lower Acceptable Band: $14.0^\circ\text{C} \le T < 21.0^\circ\text{C}$: $$S_T = \left(\frac{T - 14.0}{21.0 - 14.0}\right) \cdot 100.0$$ - Upper Acceptable Band: $24.0^\circ\text{C} < T \le 33.0^\circ\text{C}$: $$S_T = \left(\frac{33.0 - T}{33.0 - 24.0}\right) \cdot 100.0$$ - Out of Bounds: $T < 14.0^\circ\text{C}$ or $T > 33.0^\circ\text{C} \implies S_T = 0.0$

2. Relative Humidity Component Score ($S_H$, Weight $w_H = 0.25$)

Designed to inhibit respiratory drying ($<40\%$) and mold proliferation ($>60\%$): - Optimal Hygric Band: $40.0\% \le \text{RH} \le 60.0\% \implies S_H = 100.0$ - Lower Acceptable Band: $15.0\% \le \text{RH} < 40.0\%$: $$S_H = \left(\frac{\text{RH} - 15.0}{40.0 - 15.0}\right) \cdot 100.0$$ - Upper Acceptable Band: $60.0\% < \text{RH} \le 85.0\%$: $$S_H = \left(\frac{85.0 - \text{RH}}{85.0 - 60.0}\right) \cdot 100.0$$ - Out of Bounds: $\text{RH} < 15.0\%$ or $\text{RH} > 85.0\% \implies S_H = 0.0$

3. MQ-135 Relative Gas Component Score ($S_G$, Weight $w_G = 0.25$)

Evaluated relative to the rolling clean-air baseline ($V_{\text{base}}$): $$\text{Ratio} = \frac{V_{\text{pin}}}{V_{\text{base}}}$$ - Clean Air: $\text{Ratio} \le 1.05 \implies S_G = 100.0$ - Elevated Contamination: $1.05 < \text{Ratio} < 2.50$: $$S_G = \left(\frac{2.50 - \text{Ratio}}{2.50 - 1.05}\right) \cdot 100.0$$ - Severe Degradation: $\text{Ratio} \ge 2.50 \implies S_G = 0.0$ - Exclusion Clause: If the sensor is warming up ($\text{uptime} < 300\text{ s}$) or the baseline is unconditioned, $S_G$ is assigned None and excluded from the normalized weighting calculation.

4. Ambient Lighting Component Score ($S_L$, Weight $w_L = 0.10$)

Based on LDR 12-bit ADC raw count: - Adequate / Bright Illumination: $\text{ADC} \ge 1700 \implies S_L = 100.0$ - Dim Ambient Illumination: $250 \le \text{ADC} < 1700 \implies S_L = 85.0$ - Dark Environment: $\text{ADC} < 250 \implies S_L = 50.0$

5. Acoustic Component Score ($S_S$, Weight $w_S = 0.10$)

Based on LM393 analog swing and digital trigger: - Quiet Study / Lab Environment: $\text{Swing} < 400\text{ and DO} = 0 \implies S_S = 100.0$ - Moderate Background Acoustic Activity: $400 \le \text{Swing} < 1200\text{ and DO} = 0 \implies S_S = 80.0$ - High Acoustic Disturbance: $\text{Swing} \ge 1200\text{ or DO} = 1 \implies S_S = 40.0$

4.2 Dynamic Normalization & Missing Data Invariants

When an optional sensor is offline or unconditioned (such as the MQ-135 during heater warm-up), the active weights are normalized dynamically: $$\text{RCI} = \frac{\sum_{i \in \text{available}} w_i \cdot S_i}{\sum_{i \in \text{available}} w_i}$$

Boundary Invariants: 1. Core Sensor Requirement: If either temperature or humidity is missing or invalid, RCI returns score: null, status: "INDETERMINATE", and color_band: "gray". 2. Coverage Threshold: If total active weight coverage is $<50\%$, the score returns null with INDETERMINATE. 3. Freshness Guarantee: If the observation is older than $120\text{ seconds}$, the score returns null with is_stale: true.

5. Experimental Indoor PM2.5 & CO₂ Estimators

Implemented in backend/intelligence/indoor_estimation.py.

[!IMPORTANT] Regulatory and Clinical Disclosures: Because the physical sensor cluster lacks an optical laser particle counter (e.g., Plantower PMS5003) and an optical non-dispersive infrared (NDIR) $\text{CO}_2$ chamber, these estimators are classified as experimental demonstration proxies. They are tagged with label EXPERIMENTAL ESTIMATE, method heuristic_proxy, and calibration status uncalibrated_heuristic.

5.1 Indoor PM2.5 Proxy Estimator (estimate_indoor_pm25)

Computes a deterministic particulate concentration estimate clamped to $2.0\text{--}500.0\text{ }\mu\text{g/m}^3$: $$\text{PM}{2.5, \text{est}} = \text{Base}{\text{particle}} + \Delta_{\text{gas}} + \Delta_{\text{RH}}$$

  1. Particulate Baseline ($\text{Base}_{\text{particle}}$): If outdoor $\text{PM}{2.5}$ is available from the regional Open-Meteo model, an indoor building penetration factor of $60\%$ is applied: $$\text{Base}{\text{particle}} = \max(5.0,\ \text{PM}_{2.5, \text{outdoor}} \cdot 0.60)$$ If outdoor data is unavailable, a standard clean-room default ($15.0\text{ }\mu\text{g/m}^3$) is used.
  2. Gas Excursion Offset ($\Delta_{\text{gas}}$): Aerosol and smoke events typically elevate metal-oxide surface conductivity: $$\Delta_{\text{gas}} = \max(0.0,\ (\text{Ratio} - 1.0) \cdot 35.0)$$
  3. Hygroscopic Moisture Adjustment ($\Delta_{\text{RH}}$): High humidity ($\text{RH} > 60\%$) promotes hygroscopic particle swelling: $$\Delta_{\text{RH}} = \left(\frac{\text{RH} - 60.0}{40.0}\right) \cdot 8.0$$

5.2 Indoor CO₂ Proxy Estimator (estimate_indoor_co2)

Computes an indoor metabolic accumulation proxy clamped to $400\text{--}5000\text{ ppm}$: $$\text{CO}{2, \text{est}} = \left[\text{CO}{2, \text{nominal}} + \left((\text{Ratio} - 1.0)^{1.35} \cdot 750.0\right)\right] \cdot C_{\text{env}}(T, \text{RH})$$

  • Nominal Reference: $\text{CO}_{2, \text{nominal}} = 420.0\text{ ppm}$ (assumed atmospheric clean-air background).
  • Non-Linear Excursion: Models metabolic respiration accumulation non-linearly with gas ratio.
  • Environmental Compensation ($C_{\text{env}}$): Corrects for MQ-135 temperature/humidity cross-sensitivity relative to standard calibration conditions ($20^\circ\text{C}, 65\%\text{ RH}$): $$C_{\text{env}} = 1.0 - 0.005 \cdot (T - 20.0) - 0.002 \cdot (\text{RH} - 65.0)$$

6.2 Magnus-Tetens Psychrometric Formulations

Implemented in backend/intelligence/comparison_engine.py:

1. Temperature Delta ($\Delta T$)

$$\Delta T = T_{\text{indoor}} - T_{\text{outdoor}}\quad (^\circ\text{C})$$ Direction: outdoor_cooler ($\Delta T \ge 1.0$), outdoor_warmer ($\Delta T \le -1.0$), or thermal_equilibrium.

2. Relative Humidity Delta ($\Delta\text{RH}$)

$$\Delta\text{RH} = \text{RH}{\text{indoor}} - \text{RH}{\text{outdoor}}\quad (\text{pp})$$ Strictly labeled in percentage points (pp), never percent change.

3. Dew Point Temperature ($T_{\text{dew}}$)

Using standard Magnus-Tetens coefficients ($a = 17.27, b = 237.7^\circ\text{C}$): $$\alpha(T, \text{RH}) = \frac{a \cdot T}{b + T} + \ln\left(\frac{\text{RH}}{100.0}\right)$$ $$T_{\text{dew}} = \frac{b \cdot \alpha(T, \text{RH})}{a - \alpha(T, \text{RH})}\quad (^\circ\text{C})$$

4. Volumetric Absolute Humidity ($\text{AH}$)

Calculates total moisture mass per unit volume of air ($\text{g/m}^3$): $$P_{\text{sat}}(T) = 6.112 \cdot \exp\left(\frac{17.67 \cdot T}{T + 243.5}\right)\quad (\text{hPa})$$ $$\text{AH} = \frac{P_{\text{sat}}(T) \cdot \text{RH} \cdot 2.1674}{273.15 + T}\quad (\text{g/m}^3)$$ $$\Delta\text{AH} = \text{AH}{\text{indoor}} - \text{AH}{\text{outdoor}}\quad (\text{g/m}^3)$$

6.3 Holistic Ventilation Favourability Decision

The engine evaluates three interdependent vectors: 1. Thermal Advantage: Does opening windows cool a warm room ($T_{\text{in}} > 24^\circ\text{C}$ and $\Delta T \ge 1.0^\circ\text{C}$)? 2. Moisture Migration: Will outdoor air dehumidify the room ($\Delta\text{AH} \ge 1.5\text{ g/m}^3$) or introduce dampness? 3. Outdoor Air Quality Filter: - $\text{US AQI} \le 75$: Favourable outdoor air quality. - $76 \le \text{US AQI} \le 100$: Intermediate air quality (cautionary / brief ventilation only). - $\text{US AQI} > 100$: Unfavourable air quality (natural ventilation strictly inhibited).

Returns one of: favourable, unfavourable, mixed, or indeterminate.

11. Viva Defense Alignment & Examiner Question Preparation


Q1: Why does the system use a relative baseline for the MQ-135 instead of displaying direct ppm CO₂?




Answer: The MQ-135 is a broad-band chemoresistive metal-oxide semiconductor (SnO₂) sensor without an optical absorption chamber. It responds non-selectively to ammonia, nitrogen oxides, ethanol, benzene, smoke, and $\text{CO}_2$. Displaying uncalibrated direct ppm numbers would misrepresent the sensor's capabilities. Using a 20% trimmed mean clean-air rolling baseline allows the system to detect contamination spikes without making unverified chemical claims.




Q2: Why is the humidity difference reported as percentage points (pp) rather than percent change?




Answer: Relative humidity is already expressed as a percentage of saturation vapor pressure. A shift from $50\%$ to $60\%$ is an absolute difference of $10$ percentage points ($\text{pp}$), whereas a "10 percent increase" would imply $55\%$. Using $\text{pp}$ preserves metrological precision.




Q3: Why does the system calculate both relative humidity delta and absolute humidity?




Answer: Relative humidity is temperature-dependent. Cold outdoor air at $98\%\text{ RH}$ ($24.7^\circ\text{C}$) can contain more or less moisture mass than indoor air at $57.2\%\text{ RH}$ ($27.5^\circ\text{C}$). By using the Magnus-Tetens formula to compute volumetric absolute humidity in $\text{g/m}^3$, the decision engine determines actual moisture migration direction when windows are opened.




Q4: How does the system handle Open-Meteo API timeouts or regional model failures?




Answer: The outdoor service implements a 15-minute server-side in-memory cache and a 5-second timeout. If the upstream provider experiences a temporary outage (such as HTTP 503), the backend returns cached data tagged as stale_cached. This isolates the local sensor telemetry, ensuring outdoor API errors never trigger false indoor environmental alarms.




Q5: What is the purpose of the 9-subsystem diagnostics matrix?




Answer: Conventional IoT monitors fail to distinguish between hardware faults and environmental hazards. If a sensor drops offline, basic monitors often report $0$ and trigger a false alarm. SIEIS isolates hardware states (DHT22 disconnected, MQ-135 warming up, telemetry stale) from environmental conditions, reporting clear diagnostic notices before generating recommendations.
